## 用户管理模块

用户管理模块负责系统用户的全生命周期管理，包括用户的增删改查、密码重置、状态启禁以及角色分配等功能。该模块是系统权限控制的基础，所有用户操作都必须通过身份验证和权限校验。

后端控制器 `eadm_user_controller.erl` 实现了完整的用户管理逻辑。当用户访问 `/user` 路径时，`index/1` 函数会检查用户的认证状态和权限（`usermanage` 权限）。如果用户已认证且拥有相应权限，则返回成功响应，否则返回重定向或鉴权失败信息。用户列表的加载通过 `search/1` 函数实现，该函数会查询 `vi_user` 视图，返回所有用户的基本信息，如登录名、用户名、邮箱和状态等。

前端通过 `user.js` 文件中的 `loadUserData()` 函数与后端交互。该函数使用 `$.getJSON('/user')` 发起异步请求获取用户数据，并利用 DataTables 插件将数据渲染到表格中。表格的列标题通过 `i18n-user.js` 中的国际化配置进行翻译。用户界面提供了丰富的操作按钮，包括编辑、启禁、重置密码和删除等。

关键的用户操作如新增、编辑、删除等通过相应的后端函数实现。例如，`add/1` 函数在接收到 POST 请求后，会先验证登录名、邮箱和密码的格式，然后调用 `eadm_pgpool:equery/3` 执行 SQL 插入语句。类似地，`delete/1` 函数通过更新 `deleted` 字段来实现软删除。权限校验贯穿所有操作，确保只有拥有 `usermanage` 权限的用户才能执行管理操作。

## 角色权限模块

角色权限模块实现了基于角色的访问控制（RBAC），允许管理员创建角色并为角色分配不同的系统权限，然后将角色分配给用户，从而实现细粒度的权限管理。

后端控制器 `eadm_role_controller.erl` 负责角色的管理。`add/1` 函数处理角色的创建，将角色名称插入 `eadm_role` 表。核心的权限管理功能由 `updatepermission/1` 函数实现。该函数接收一个包含各种权限布尔值的参数映射，将其构造成一个嵌套的 Erlang Map，然后使用 `thoas:encode/1` 将其序列化为 JSON 字符串，最后更新数据库中的 `rolepermission` 字段。权限结构包括仪表盘、健康、财务、定时任务、用户管理、设备管理等多个模块，每个模块下又有更细粒度的权限，如财务模块下的 `finlist`（查看）、`finimp`（导入）和 `findel`（删除）。

前端 `role.js` 提供了角色管理的用户界面。`loadRoleData()` 函数加载角色列表并渲染到表格中。当用户点击“编辑角色”按钮时，`loadPermission/1` 函数被调用，通过 `$.getJSON('/permission/' + roleId)` 获取指定角色的权限配置，并将返回的 JSON 数据绑定到模态框中的复选框上，实现权限的可视化编辑。提交时，`editPermission/1` 函数收集所有复选框的状态，构造请求参数并发送到 `/permission/edit` 接口。

用户与角色的关联通过 `userroleadd/1` 和 `userroledel/1` 两个函数管理，它们分别向 `eadm_userrole` 关联表中插入和删除记录。整个流程确保了权限的动态分配和回收。

## 设备管理模块

设备管理模块用于管理系统的物理设备，如智能手表、充电宝等。它提供了设备的增删改查、状态切换、以及设备与用户之间的分配关系管理。

后端控制器 `eadm_device_controller.erl` 实现了设备管理的核心功能。`add/1` 函数在添加设备时，会先检查设备号是否已存在，避免重复。`edit/1` 和 `delete/1` 函数分别处理设备信息的更新和软删除。`toggle_status/1` 函数是该模块的一个特色功能，用于启用或禁用设备。它通过查询当前状态并取反来实现状态切换，并返回相应的成功提示（“设备启用成功！”或“设备禁用成功！”）。

设备与用户的分配关系由 `assign/1` 和 `unassign/1` 函数管理。`assign/1` 在分配前会检查该设备是否已分配给该用户，防止重复分配。`device_users/1` 函数则用于查询分配给某个设备的所有用户。

前端 `device.js` 构建了一个功能完整的设备管理界面。`initDeviceTable()` 初始化一个包含操作列的 DataTable，操作列中包含编辑、启禁、管理用户和删除按钮。`loadDeviceUsers()` 函数用于在模态框中加载特定设备的用户列表。`toggleDeviceStatus()` 函数封装了状态切换的 AJAX 请求，提供了良好的用户体验。

## 财务统计模块

财务统计模块用于导入、查询和管理用户的财务交易数据，支持从多种来源（如支付宝、微信、银行）导入数据，并提供数据导出功能。

后端控制器 `eadm_finance_controller.erl` 的 `search/1` 函数根据查询参数（来源、收支类型、时间范围）从 `fn_paybilldetail` 表中查询数据。查询前会进行时间格式验证和时间跨度检查（默认不超过366天）。`delete/1` 函数实现财务数据的软删除。`upload/1` 函数是数据导入的核心，它根据 `importType` 参数处理不同格式的上传数据，并将其插入数据库。

前端 `finance.js` 提供了强大的数据交互功能。`loadFinanceData()` 函数根据用户选择的条件加载财务数据并渲染表格。`exportFinanceData()` 函数利用 `XLSX` 库将当前表格数据导出为 Excel 文件。`processFile()` 函数是数据导入的前端处理逻辑，它首先调用 `readAndProcessWorkbook()` 读取文件，然后根据导入类型调用相应的映射函数（如 `mapAlipayFields`）将原始数据字段映射到系统字段，最后将处理好的数据通过 AJAX 发送到 `/upload/finance` 接口。

## 健康监测模块

健康监测模块用于查询和展示用户的健康数据，如步数、心率、体温、血压和睡眠等。

后端控制器 `eadm_health_controller.erl` 的 `search/1` 函数根据 `dataType` 参数查询不同的健康数据表。例如，当 `dataType` 为 `"1"` 时，查询 `lc_watchstep` 表获取步数数据；为 `"2"` 时，查询 `lc_watchhb` 表获取心率数据。查询结果通过 `eadm_utils:pg_as_json/2` 转换为 JSON 格式返回。

前端 `health.js` 的 `loadHealthData()` 函数负责加载数据并渲染表格。它会根据 `dataType` 发起请求，并在数据加载后调用 `buildDynamicData()` 函数构建表格列和数据。对于睡眠类型等需要翻译的字段，它会使用 `translateSleepType()` 函数将数据库中的数字代码（如1, 2, 3）转换为可读的中文（如“深度睡眠”、“浅度睡眠”）。

## 定时任务模块

定时任务模块基于 `ecron` 库实现，允许用户创建、编辑、启用/禁用和删除定时任务。系统启动时会自动调用 `init/0` 函数，加载并调度所有状态为“启用”的任务。

后端控制器 `eadm_crontab_controller.erl` 的 `schedule_job/1` 函数是核心。它解析任务的 `cronmfa` 字符串（格式为 `Module:Function/Arguments`），检查模块和函数是否存在，然后使用 `ecron:add/7` 将任务添加到调度器中。`toggle/1` 函数用于切换任务状态。当激活任务时，它会先从数据库中查询任务的详细信息（包括 `cronexp` 和 `cronmfa`），然后调用 `schedule_job/1` 进行调度；当停用任务时，则调用 `ecron:delete/1` 从调度器中移除。

前端 `crontab.js` 提供了任务管理界面。`addCron()` 函数提交新任务，`toggleCron()` 函数处理状态切换。`loadCronDetail()` 函数用于查询和展示任务的执行日志。

## 地理位置服务模块

地理位置服务模块用于展示设备的轨迹回放，基于高德地图 API 实现。

后端控制器 `eadm_location_controller.erl` 的 `search/1` 函数查询设备的定位数据。它会先检查用户是否有权限访问指定的设备（通过查询 `eadm_userdevice` 表），然后从 `lc_carlocdaily` 表中查询指定时间范围内的经纬度数据。

前端 `location.js` 是该模块的核心。它使用 `AMapLoader` 加载高德地图 SDK。`loadLocationData()` 函数获取轨迹数据后，`reloadCarReplay()` 函数会创建一个 `AMap.Polyline` 对象绘制轨迹线，并创建一个 `AMap.Marker` 对象作为移动的小汽车。通过 `carMarker.moveAlong()` 方法，可以实现小汽车沿轨迹线的动画移动，支持暂停、继续和停止操作。
