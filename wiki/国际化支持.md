## 简介
`eadm` 系统通过前端 JavaScript 文件实现国际化（i18n）功能，支持多语言界面展示。当前系统主要通过 `priv/assets/i18n/` 目录下的 `i18n-*.js` 文件管理不同模块的多语言词条，如用户管理、健康数据、定时任务等。语言切换基于全局变量 `defaultLanguage` 控制，默认为中文（`zh`）。本文档详细说明其国际化实现机制、扩展方法及部署维护建议。

## 前端多语言资源管理

系统将多语言资源按功能模块拆分为独立的 JavaScript 文件，存放于 `priv/assets/i18n/` 目录下。每个文件定义一个全局对象，用于存储特定模块的翻译内容。

例如：
- `i18n-user.js`：用户管理模块的列名翻译
- `i18n-health.js`：健康数据模块的列名及睡眠类型翻译
- `i18n-crontab.js`：定时任务模块的列名翻译
- `i18n-role.js`：角色管理模块的列名翻译

每个语言包采用如下结构：
```javascript
window.i18nUser = window.i18nUser || {};

i18nUser.columnName = {
  zh: {
    "id": "用户id",
    "username": "用户姓名"
  },
  en: {
    "id": "UserId",
    "username": "UserName"
  }
};
```

这些翻译数据主要用于动态渲染表格列名、按钮文本等界面元素。

## 语言切换机制

系统通过全局变量 `defaultLanguage` 控制当前显示语言，定义在 `basic.js` 文件中，默认值为 `'zh'`。

```javascript
defaultLanguage = 'zh';
```

各模块通过调用 `translateColumnNames()` 函数从对应语言包中获取当前语言的翻译文本。例如在 `user.js` 中：

```javascript
function translateColumnNames(columnName) {
  const translations = i18nUser.columnName[defaultLanguage];
  return translations[columnName] || columnName;
}
```

该函数根据 `defaultLanguage` 的值（如 `'zh'` 或 `'en'`）从对应的翻译对象中查找匹配的文本。若未找到，则返回原始键名作为兜底。

此机制在加载表格数据时被调用，动态设置 DataTables 的列标题。

## 新增语言包与翻译词条

### 添加新语言
要添加新语言（如西班牙语 `es`），需在现有语言包中扩展对应语言对象。例如，在 `i18n-user.js` 中添加：

```javascript
i18nUser.columnName = {
  zh: { /* 中文翻译 */ },
  en: { /* 英文翻译 */ },
  es: {
    "id": "ID de usuario",
    "username": "Nombre de usuario",
    "email": "Correo electrónico"
  }
};
```

同时，需提供语言切换接口（当前系统暂未实现 UI 切换控件），可通过修改 `defaultLanguage` 变量值来测试。

### 添加新翻译词条
当新增界面字段时，需在对应模块的语言包中添加新的键值对。例如，若用户模块新增“手机号”字段，则在 `i18n-user.js` 中添加：

```javascript
"phone": "手机号"  // 在 zh 对象中
"phone": "Phone"  // 在 en 对象中
```

并在前端代码中使用 `translateColumnNames("phone")` 获取翻译。

## 后端国际化参与情况

目前，后端（Erlang 模块）**不直接参与界面文本的国际化处理**。所有界面显示文本均由前端 JavaScript 语言包负责翻译。

然而，后端返回的错误消息（如 `resdata[0].Alert`）可能包含中文提示信息，这类消息目前**硬编码在后端逻辑中**，并未通过语言包进行管理。例如：

```javascript
if (resdata && resdata.length > 0 && resdata[0].Alert) {
    showWarningToast(resdata[0].Alert);
}
```

这意味着错误提示的多语言支持需要后端配合改造，当前系统尚未实现。

## 前后端语言包同步策略

当前系统**缺乏自动化的前后端语言包同步机制**。由于后端错误消息未使用标准语言包格式，无法与前端 `i18n-*.js` 文件进行统一管理。

建议未来改进方向：
1. 后端统一使用 JSON 格式返回错误码与消息模板
2. 前端根据错误码查询本地语言包获取对应语言的提示信息
3. 建立共享的翻译词条仓库，通过构建脚本同步前后端语言资源

目前，任何涉及后端错误消息的变更需手动协调前后端开发人员更新。

## 多语言部署操作指南

### 部署前准备
1. 确认 `priv/assets/i18n/` 目录下所有语言包完整且无语法错误
2. 检查新增字段是否已在各语言包中添加对应翻译
3. 若启用新语言，确保 `defaultLanguage` 可被外部配置（如通过 URL 参数或 localStorage）

### 部署步骤
1. 将 `priv/assets/i18n/` 和 `priv/assets/js/` 文件随静态资源一同部署
2. 确保 Web 服务器正确提供 `.js` 文件的 MIME 类型
3. 清除浏览器缓存或使用版本化文件名防止旧语言包缓存

### 语言切换模拟（调试用）
可通过浏览器控制台临时切换语言：
```javascript
defaultLanguage = 'en';
loadUserData(); // 重新加载数据以应用新语言
```

## 翻译文件维护最佳实践

1. **模块化管理**：保持按功能拆分语言包，避免单一巨大文件
2. **键名一致性**：使用小写英文键名，避免空格和特殊字符
3. **兜底机制**：前端翻译函数应始终返回键名本身作为默认值
4. **版本控制**：将语言包纳入 Git 管理，便于追踪翻译变更
5. **自动化校验**：编写脚本检查各语言包是否包含所有必要键名
6. **避免后端硬编码**：逐步将后端错误消息替换为错误码机制
7. **文档化词条**：为复杂字段添加注释说明上下文用途

通过遵循上述实践，可确保 `eadm` 系统的多语言功能可维护、可扩展，并为未来支持更多语言奠定基础。
