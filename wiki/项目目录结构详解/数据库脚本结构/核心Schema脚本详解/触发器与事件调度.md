## 引言
本系统通过数据库事件调度器和触发器实现关键自动化任务，包括定时清理日志、更新统计缓存和监控状态变更。系统支持多种数据库（MySQL、Kingbase、PostgreSQL），并结合后端Erlang调度模块 `eadm_crontab_controller` 实现跨平台任务协调。本文详细阐述 `ev_DashBoard.sql` 和 `dts.sql` 脚本中的自动化机制，说明其配置方式、执行逻辑及与后端的协同工作原理。

## 事件调度器机制

事件调度器用于执行周期性任务，如每日统计报表生成。不同数据库的配置方式如下：

### MySQL 与 Kingbase 配置
在 MySQL 和 Kingbase 中，事件调度器需通过 `EVENT_SCHEDULER` 系统变量启用。`ev_DashBoard.sql` 脚本定义了一个每日执行的事件：

```sql
CREATE EVENT ev_DashBoard
  ON SCHEDULE EVERY 1 DAY
  ENABLE
  COMMENT '定时任务_每日首页报表统计'
  DO BEGIN
    CALL proc_DashBoard(CURRENT_DATE);
  END;
```

- **调度频率**：`EVERY 1 DAY` 表示每天执行一次。
- **状态控制**：`ENABLE` 表示事件处于激活状态。
- **任务内容**：调用存储过程 `proc_DashBoard`，传入当前日期作为参数。

该事件在系统启动时自动加载，无需手动干预。

### PostgreSQL 配置
PostgreSQL 使用 `pg_cron` 扩展实现事件调度。`pgcron.sql` 脚本中通过 `cron.schedule_in_database` 函数注册任务：

```sql
select cron.schedule_in_database('eadm_dashboard', '0 4 * * *', 'call prod_dashboard(current_date);', 'eadm');
```

- **调度表达式**：`0 4 * * *` 表示每天凌晨4点执行。
- **执行内容**：调用 `prod_dashboard` 存储过程。
- **数据库绑定**：任务在 `eadm` 数据库中运行。

`pg_cron` 是一个后台工作进程，独立于主应用运行，确保高可靠性。

## 触发器机制

触发器用于响应数据变更，实现数据迁移与同步。`dts.sql` 脚本在 Kingbase 和 PostgreSQL 中定义了多个数据迁移操作。

### PostgreSQL 与 Kingbase 触发逻辑
`dts.sql` 脚本通过 `TRUNCATE` 和 `INSERT INTO ... SELECT` 组合实现数据迁移：

```sql
TRUNCATE TABLE "public"."carlocdaily";
INSERT INTO "public"."carlocdaily" (...) 
SELECT ... FROM carlocdaily_bak;
```

- **触发时机**：脚本通常由外部调度器（如 `pg_cron` 或后端 `eadm_crontab_controller`）调用，而非基于 `INSERT/UPDATE/DELETE` 自动触发。
- **时区处理**：使用 `AT TIME ZONE 'UTC'` 和 `INTERVAL '8 hours'` 进行时区转换，确保时间字段一致性。
- **数据清洗**：`CASE` 表达式用于转换布尔值，如 `CASE "Deleted" WHEN 0 THEN FALSE ELSE TRUE END`。

该机制适用于批量数据同步，避免频繁触发影响性能。

## 后端协同机制

后端 Erlang 模块 `eadm_crontab_controller` 与数据库事件调度器协同工作，避免任务重复执行。

### 任务调度流程
1. **初始化**：系统启动时调用 `init/0` 函数，加载 `ecron` 应用。
2. **加载任务**：从 `eadm_crontab` 表中查询所有 `cronstatus = 0`（启用）且未删除的任务。
3. **调度执行**：使用 `ecron:add/7` 将任务注册到 Erlang 调度器，确保单例执行（`{singleton, true}`）。

```erlang
schedule_job(#{<<"cronexp">> := CronExp, <<"cronmfa">> := CronMFA}) ->
    [ModStr, FunStr, ArgsStr] = binary:split(CronMFA, [<<":">>, <<"/">>], [global]),
    Mod = binary_to_atom(ModStr, utf8),
    Fun = binary_to_atom(FunStr, utf8),
    Args = parse_args(ArgsStr),
    JobFun = fun() -> apply(Mod, Fun, Args) end,
    ecron:add(ecron_local, JobId, binary_to_list(CronExp), {erlang, apply, [JobFun, []]}, ...).
```

### 避免重复执行
- **状态同步**：数据库中的 `cronstatus` 字段（0启用，1禁用）与 `ecron` 调度器状态保持一致。
- **任务ID唯一性**：使用 `job_{id}` 作为任务ID，确保每个任务在 `ecron` 中唯一。
- **动态更新**：编辑或切换任务状态时，先删除旧任务，再添加新任务。

## 启用与验证步骤

### 启用事件调度器
1. **MySQL/Kingbase**：执行 `SET GLOBAL EVENT_SCHEDULER = ON;`。
2. **PostgreSQL**：执行 `CREATE EXTENSION IF NOT EXISTS pg_cron;`。
3. 执行对应 SQL 脚本（`ev_DashBoard.sql` 或 `pgcron.sql`）。

### 验证任务执行
1. **检查事件状态**：
   - MySQL/Kingbase：`SHOW EVENTS;`
   - PostgreSQL：`SELECT * FROM cron.job;`
2. **查看执行日志**：
   - PostgreSQL：`SELECT * FROM cron.job_run_details ORDER BY start_time DESC LIMIT 5;`
   - 系统日志：检查 `sys_cronlog` 表或应用日志。
3. **手动触发验证**：
   - 执行 `CALL proc_DashBoard(CURRENT_DATE);` 并检查 `eadm_dashboard` 表数据。

## 常见问题排查

### 事件未启动
- **检查调度器状态**：确认 `EVENT_SCHEDULER` 或 `pg_cron` 已启用。
- **权限问题**：确保数据库用户有执行 `CREATE EVENT` 或 `cron.schedule` 的权限。
- **语法错误**：检查 SQL 脚本中的时间表达式和存储过程名称。

### 触发器未生效
- **脚本未执行**：确认 `dts.sql` 脚本已由调度器调用。
- **时区问题**：检查 `AT TIME ZONE` 和 `INTERVAL` 计算是否正确。
- **数据源为空**：确认 `carlocdaily_bak` 等源表存在且有数据。

### 后端任务冲突
- **ecron 未加载**：检查日志中是否有 `ecron 应用启动失败` 错误。
- **MFA 格式错误**：确保 `cronmfa` 字段为 `模块:函数/参数` 格式，如 `eadm_dashboard:refresh/1`。
- **函数不存在**：确认模块和函数已编译并导出。

## 结论
本系统通过数据库原生事件调度器与后端 Erlang 调度模块的协同，实现了高效、可靠的自动化任务管理。`ev_DashBoard.sql` 和 `dts.sql` 脚本分别处理定时统计和数据迁移，而 `eadm_crontab_controller` 确保任务调度的统一性和避免重复执行。建议在生产环境中优先使用后端调度器管理任务，以获得更好的监控和错误处理能力。
