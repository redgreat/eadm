## 用户管理模块

`user.js` 模块负责用户信息的展示、增删改查及角色分配功能。该模块通过 AJAX 与后端 `eadm_user_controller.erl` 进行 RESTful 交互，实现完整的用户生命周期管理。

在初始化时，`loadUserData()` 函数通过 `$.getJSON('/user')` 发起 GET 请求，获取用户列表数据，并动态构建 DataTable 表格。表格列名通过 `i18nUser` 国际化模块进行本地化翻译。响应数据包含列定义 `columns` 和数据集 `data`，前端据此动态生成列结构。

用户新增操作通过 `addUser()` 函数实现，构造包含 `loginName`、`email`、`userName`、`password` 的参数对象，通过 POST 请求 `/user/add` 提交至后端。编辑、删除、禁用、重置密码等操作均采用类似模式，通过 `userId` 路径参数定位目标资源，符合 RESTful 设计规范。

用户角色管理通过 `loadUserRole()` 和 `addUserRole()` 实现。前者通过 `/userrole/{userId}` 获取指定用户的角色列表，后者通过 `/userrole/add` 批量分配角色。角色分配界面通过 `loadRoleList()` 加载可选角色列表，该接口对应后端 `/role/{userId}`，返回当前用户尚未分配的角色。

所有 AJAX 请求均包含统一的错误处理逻辑：若响应包含 `Alert` 字段，则调用 `showWarningToast()` 显示警告信息；否则提示“服务器运行错误”。后端控制器 `eadm_user_controller.erl` 在鉴权失败、参数校验错误或数据库操作异常时返回相应的 `Alert` 消息，确保前后端错误信息一致。

**模块初始化与事件监听**：
- `$(document).ready()` 中调用 `loadUserData()` 初始化用户列表
- 绑定“刷新”、“新增”、“编辑”等按钮的点击事件
- 通过 DataTable 的 `on('click', '.delete-user-btn', ...)` 注册操作按钮事件代理

## 角色管理模块

`role.js` 模块提供角色的增删改查及权限配置功能。其前端逻辑与用户模块类似，但权限管理部分更为复杂。

`loadRoleData()` 函数通过 `$.getJSON('/role')` 获取角色列表，渲染为 DataTable。新增角色通过 `addRole()` 发送 POST 请求至 `/role/add`。

核心功能在于权限编辑。点击“编辑角色”按钮后，`loadPermission()` 函数通过 `/permission/{roleId}` 获取指定角色的权限配置，并填充至模态框中的复选框。权限数据结构为嵌套 JSON，包含 `dashboard`、`health`、`locate`、`finance`（含 `finlist`、`finimp`、`findel`）、`crontab`、`usermanage` 及 `device`（含 `devlist`、`devadd` 等）等模块的访问控制。

权限提交通过 `editPermission()` 函数实现，收集所有复选框状态，构造包含 `roleId` 及各权限布尔值的参数对象，发送至 `/permission/edit`。后端 `eadm_role_controller.erl` 的 `updatepermission/1` 函数接收这些参数，构建嵌套的 Erlang Map，序列化为 JSON 存储至数据库 `rolepermission` 字段。

权限数据的获取与存储体现了前后端的紧密协作：前端以扁平化的表单形式收集权限，后端将其组织为结构化的 JSON 对象，实现了灵活的权限模型。

## 设备管理模块

`device.js` 模块实现设备的全生命周期管理，包括增删改查、启禁用、用户分配等复杂操作。

模块采用模块化设计，`initDeviceTable()` 初始化 DataTable，定义列渲染函数，如将 `enable` 字段渲染为“启用”/“禁用”标签。事件监听通过事件代理注册在表格容器上，如 `.edit-device`、`.delete-device` 等按钮的点击事件。

数据交互方面：
- 查询：`loadDeviceData()` 通过 `/device` GET 接口查询设备列表，支持按设备号过滤。
- 新增：`addDevice()` 通过 `/device/add` POST 接口添加设备，数据以 JSON 格式提交。
- 编辑：`editDevice()` 通过 `/device/edit` POST 接口更新设备信息。
- 删除：`deleteDevice()` 通过 `/device/delete/{deviceNo}` DELETE 接口软删除设备。
- 启禁用：`toggleDeviceStatus()` 通过 `/device/toggle` POST 接口切换设备状态。

设备与用户关联管理是本模块的亮点。`loadDeviceUsers()` 通过 `/device/users/{deviceNo}` 获取设备关联的用户列表。`addDeviceUser()` 通过 `/device/assign` POST 接口分配用户，`unassignDeviceUser()` 通过 `/device/unassign/{id}` DELETE 接口取消分配。前端通过模态框和确认对话框提供友好的交互体验。

后端 `eadm_device_controller.erl` 对每个操作都进行了严格的权限校验和业务逻辑验证，如添加设备前检查设备号是否已存在，确保数据一致性。

## 登录与会话管理

`login.js` 模块负责用户登录流程和会话管理。

`login()` 函数是核心，它：
1. 禁用登录按钮防止重复提交。
2. 收集表单数据 `loginName` 和 `password`。
3. 通过 AJAX POST 请求 `/login` 提交至后端。
4. 处理响应：若 `resdata[0].logined === 0`，显示错误信息并启用按钮；若为 1，则修改按钮文本为“登录成功，跳转中...”，并延迟 500 毫秒后跳转至首页。

后端 `eadm_login_controller.erl`（未提供源码，但可推断）在验证成功后设置会话 Cookie，前端通过重定向 `/` 进入主应用。错误处理包含网络错误和无效响应的捕获，确保用户体验。

此外，模块还实现了辅助功能：
- 页面加载时设置页脚版权年份。
- 绑定回车键事件，允许用户按 Enter 键登录。

## 仪表盘数据聚合与图表渲染

`dashboard.js` 模块负责从后端聚合数据并渲染可视化图表。

`loadChart()` 函数通过 `$.getJSON('/dashboard')` 获取数据。响应数据为一个包含 13 个元素的数组，分别对应：
- `resdata[0-3]`：周维度的 location、steps、sleep、heart 数据。
- `resdata[4-7]`：年维度的 location、finance、sleep、heart 数据。
- `resdata[8-9]`：位置图表的 X 轴标签和 Y 轴数据。
- `resdata[10-12]`：财务图表的 X 轴标签、收入数据、支出数据。

前端使用 Chart.js 库渲染图表：
- 位置图表为条形图（`type: 'bar'`），展示里程数。
- 财务图表为折线图（`type: 'line'`），包含收入和支出两条数据集。

图表配置包含动画、坐标轴、图例等选项，提供良好的视觉效果。模块在加载完成后立即调用 `loadChart()`，实现数据的自动加载。

## 地图定位与响应式适配

`location.js` 和 `location-responsive.js` 模块共同实现地图轨迹回放功能。

`location.js` 使用高德地图 JS API（通过 `AMapLoader` 异步加载）。核心功能包括：
- `loadUserDevices()`：通过 `/device/user_devices` 接口获取当前用户有权访问的设备列表。
- `loadLocationData()`：通过 `/location` GET 接口查询指定时间范围和设备的轨迹数据。
- `reloadCarReplay()`：使用高德地图的 `MoveAnimation` 插件，将轨迹数据渲染为移动的小汽车动画，支持播放、暂停、停止。

`location-responsive.js` 负责响应式布局：
- `checkSidebarStatus()` 检测侧边栏展开状态，为 `body` 添加 `sidebar-open` 类。
- `adjustMapContainer()` 计算并设置 `.map-wrapper` 的 `top` 和 `bottom`，使其填充除 header 和 footer 外的整个视口。
- 监听 `window.resize` 和侧边栏切换事件，动态调整地图容器大小，并调用 `mapwong.resize()` 通知地图重绘。

两个模块分工明确：`location.js` 专注地图业务逻辑，`location-responsive.js` 专注 UI 布局适配，体现了关注点分离的设计原则。

## 通用模块开发范式

基于以上分析，可总结出新业务模块开发的标准模板与接口调用范式：

### 模块结构范式
```javascript
// 模块头部：注释、全局变量
// 模块函数：数据加载、业务操作、UI渲染
$(document).ready(function() {
    // 初始化
    // 事件绑定
});
```

### RESTful 交互范式
| 操作 | HTTP 方法 | URL 模式 | 数据格式 | 后端处理 |
| :--- | :--- | :--- | :--- | :--- |
| 查询列表 | GET | `/resource` | query string | `search/1` |
| 查询详情 | GET | `/resource/{id}` | path param | `detail/1` |
| 新增 | POST | `/resource/add` | form/json | `add/1` |
| 编辑 | POST | `/resource/edit` | json | `edit/1` |
| 删除 | DELETE | `/resource/delete/{id}` | path param | `delete/1` |

### 错误处理范式
前端统一检查响应数据中是否存在 `Alert` 字段，若有则调用 `showWarningToast()` 显示；否则提示通用错误。后端应在所有异常路径返回包含 `Alert` 的 JSON 数组。

### 事件监听范式
优先使用事件代理（event delegation），将事件绑定在父容器上，以应对动态生成的 DOM 元素。

### 状态管理范式
对于跨操作的状态（如 `currentUserId`、`currentDeviceNo`），使用全局变量在模块内共享。

遵循此范式可确保代码的一致性与可维护性，降低新功能开发的复杂度。
