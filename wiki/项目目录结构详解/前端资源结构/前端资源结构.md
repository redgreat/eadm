`priv/assets/` 目录是前端资源的核心组织结构，采用功能模块化设计，分为 `components`、`css`、`js` 和 `i18n` 四个主要子目录。这种结构清晰地分离了不同类型的前端资源，便于维护和扩展。

## JavaScript功能模块与后端对齐

### 功能模块对应关系
`js/` 目录下的JavaScript文件与后端Erlang控制器一一对应，实现了前后端功能的对齐：
- `user.js` 对应 `eadm_user_controller.erl`，处理用户管理功能。
- `device.js` 对应 `eadm_device_controller.erl`，处理设备管理功能。
- `finance.js` 对应 `eadm_finance_controller.erl`，处理财务数据管理。
- `location.js` 对应 `eadm_location_controller.erl`，处理位置数据和地图功能。
- `login.js` 对应 `eadm_login_controller.erl`，处理用户登录逻辑。
- `role.js` 对应 `eadm_role_controller.erl`，处理角色和权限管理。
- `crontab.js` 对应 `eadm_crontab_controller.erl`，处理定时任务管理。
- `dashboard.js` 对应 `eadm_dashboard_controller.erl`，处理信息看板数据展示。

### 模块化加载
每个JS文件在 `$(document).ready()` 中初始化，通过 `loadUserData()`、`loadDeviceData()` 等函数加载数据，确保页面加载完成后执行相关逻辑。

## 多语言支持

### 命名规范
`i18n/` 目录下的多语言JS文件遵循 `i18n-{模块名}.js` 的命名规范，如 `i18n-user.js`、`i18n-finance.js`，确保了文件的可识别性和一致性。

### 模块化加载
每个文件通过 `window.i18n{模块名}` 暴露翻译对象，如 `i18nUser.columnName` 定义了用户管理模块的列名翻译。`defaultLanguage` 变量控制当前语言，`translateColumnNames()` 函数根据当前语言返回对应的翻译文本。

### 实际应用
在 `user.js` 中，`translateColumnNames()` 函数被用于动态生成表格列标题，实现了列名的国际化。类似地，`finance.js` 使用 `translatesourceType()` 函数翻译来源类型，确保了财务数据的本地化展示。

## 前后端交互机制

### AJAX调用
前端通过 `$.getJSON()` 和 `$.ajax()` 调用后端Erlang控制器接口。例如，`user.js` 中的 `loadUserData()` 函数通过 `$.getJSON('/user')` 获取用户数据，`addUser()` 函数通过 `$.ajax()` 发送POST请求创建用户。

### 响应数据处理
响应数据通常为JSON格式，前端通过回调函数处理。例如，`loadUserData()` 中检查 `resdata[0].Alert` 判断是否有警告信息，否则解析 `resdata.data` 渲染表格。错误处理通过 `error` 回调函数实现，统一显示错误提示。

### 示例代码
```javascript
$.getJSON('/user', function (resdata) {
    if (resdata && resdata.length > 0 && resdata[0].Alert) {
        showWarningToast(resdata[0].Alert);
    } else {
        // 处理数据并渲染表格
    }
});
```

## 前端资源定位与扩展指南

### 资源定位
- **CSS资源**：通用样式在 `css/` 目录，组件样式在 `components/` 子目录，模块专用样式在 `css/` 下的对应文件。
- **JS资源**：功能模块在 `js/` 目录，基础工具在 `basic.js` 和 `utils.js`，地图集成在 `amaploader.js`。
- **多语言资源**：按模块在 `i18n/` 目录，命名与功能模块对应。

### 扩展指南
1. **新增功能模块**：在 `js/` 目录创建新JS文件，如 `newmodule.js`，在 `basic.js` 中添加菜单项。
2. **新增样式**：在 `css/` 目录创建新CSS文件，或在 `components/` 添加新组件样式。
3. **国际化支持**：在 `i18n/` 目录创建 `i18n-newmodule.js`，定义翻译对象，并在JS中调用 `translateColumnNames()`。
4. **地图功能扩展**：在 `amaploader.js` 中加载新插件，或在 `location.js` 中添加新功能。

通过遵循此结构和指南，开发者可以高效地定位和扩展前端资源，确保代码的可维护性和一致性。
