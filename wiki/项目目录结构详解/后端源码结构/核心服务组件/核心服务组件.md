## 认证服务模块

`eadm_auth.erl` 模块实现了基于会话（Session）的身份认证机制，确保用户请求的安全性与合法性。该模块通过检查会话中的过期时间戳（`exp`）来判断用户是否已登录并处于有效会话期内。

当请求到达时，系统首先从会话中获取 `exp` 字段，若存在且大于当前系统时间，则认为会话有效。随后提取用户的登录名（`loginname`）、用户名（`username`）和权限信息（`permission`），并更新会话的过期时间以实现自动续期功能。若会话已过期或不存在，则返回认证失败结果。

该机制结合了时间戳验证与会话存储，有效防止了会话劫持和重放攻击。同时，权限信息在认证阶段即被加载，为后续的RBAC（基于角色的访问控制）判断提供了基础数据支持。

**调用示例：**
```erlang
{AuthResult, UserInfo} = eadm_auth:auth(Req).
```

**最佳实践建议：**
- 确保 `session_expire` 配置合理，避免过长导致安全风险或过短影响用户体验。
- 敏感操作应额外进行二次认证或动态令牌验证。
- 日志中避免记录完整的用户凭证信息。

## 地理编码服务模块

`eadm_geo.erl` 模块专注于实现国际标准 WGS84 坐标系到中国国家标准 GCJ02（高德火星坐标系）的转换。此功能对于在中国境内提供地图服务的应用至关重要，因为国内地图服务（如高德、百度）均使用加密后的GCJ02坐标。

模块通过一组数学公式对原始经纬度进行偏移计算，包含正弦扰动项以增强加密效果。转换前会先判断坐标点是否位于中国境内，若不在则直接返回原坐标，避免对海外坐标进行不必要的变换。

核心函数 `wgs84_to_gcj02/1` 接收一个 `{经度, 纬度}` 元组，输出转换后的GCJ02坐标。内部使用了多个常量（如地球半长轴 `?A`、偏心率平方 `?EE`）以及自定义的正弦变换函数 `sin_convert/3` 和 `sin_convert/4` 来完成复杂的非线性偏移。

该实现无需依赖外部API，具有高性能、低延迟的优点，适用于批量坐标转换场景。

**调用示例：**
```erlang
{MgLng, MgLat} = eadm_geo:wgs84_to_gcj02({116.397026, 39.90906}).
```

**最佳实践建议：**
- 批量处理时可并行调用以提升效率。
- 对于精度要求极高的场景，建议结合高德API进行校准。
- 注意区分WGS84、GCJ02与BD09（百度坐标系）的不同用途。

## 微信集成服务模块

`eadm_wechat.erl` 模块封装了企业微信机器人消息推送功能，允许系统向指定群组发送通知消息。该模块通过HTTP请求调用企业微信Webhook接口，实现自动化告警、状态通知等功能。

模块定义了宏 `?WX_KEY` 用于配置Webhook密钥，并构建完整的请求URL与JSON数据体。消息内容需为二进制格式，支持中文字符。发送时使用 `thoas:encode/1` 将Erlang映射结构编码为JSON，并通过 `httpc:request/4` 发起POST请求。

异常处理机制完善，使用 `try...catch` 捕获网络异常或编码错误，并记录错误日志。成功发送后返回 `{<<"success">> => true}`，失败则返回 `false` 并记录详细错误信息。

**调用示例：**
```erlang
Content = unicode:characters_to_binary("系统告警：CPU使用率过高！", utf8),
Result = eadm_wechat:send_msg(Content).
```

**最佳实践建议：**
- 避免频繁发送消息，防止触发企业微信频率限制。
- 敏感信息应脱敏后再发送。
- 可结合 `eadm_push` 模块实现多通道推送（如短信、邮件）。

## Excel报表导出模块

`eadm_xlsx.erl` 模块负责解析和处理 `.xlsx` 格式的Excel文件，支持从二进制数据中提取工作表内容。其设计参考了开源项目 `erlxlsx`，并针对项目需求进行了定制优化。

模块主要提供两个API函数：
- `load/1`：解压XLSX文件并加载内容，支持内存中处理。
- `load_sheet/2`：读取工作表数据，可选择仅读取第一个工作表或全部工作表。

内部实现利用 `zip:unzip/2` 解压文件，再通过 `xmerl` 库解析XML格式的共享字符串表（`sharedStrings.xml`）和工作表数据（`sheet1.xml`）。采用递归方式提取文本内容，并根据配置决定是否将字符串转换为二进制格式。

性能优化方面，支持仅加载首张工作表以减少内存占用；同时通过 `proplists:get_value/3` 高效查找文件项，避免全量遍历。

**调用示例：**
```erlang
{ok, FileBin} = file:read_file("report.xlsx"),
Data = eadm_xlsx:load(FileBin).
```

**最佳实践建议：**
- 大文件处理时建议启用 `sheet1_only` 模式。
- 确保XML解析配置正确，避免编码问题。
- 异常路径应包含完整的错误传播机制。

## 数据库连接池管理模块

`eadm_pgpool.erl` 与 `eadm_pgpool_worker.erl` 共同构成了系统的PostgreSQL数据库连接池架构。该设计基于 `poolboy` 工具库，实现了高效、稳定的数据库连接复用机制。

`eadm_pgpool` 提供高层API，如 `connect/1`、`equery/2`、`squery/1` 和 `with_transaction/1`，屏蔽底层连接管理细节。用户可通过 `connect/2` 指定连接池名称、大小及溢出限制，实现多数据库环境下的灵活适配。

`eadm_pgpool_worker` 作为 `gen_server` 行为模块，负责实际的连接创建、SQL执行与事务管理。它实现了 `poolboy_worker` 行为，支持从连接池中获取Worker进程执行数据库操作。关键特性包括：
- 自动重连机制：当连接断开时，通过 `handle_info/2` 监听 `'EXIT'` 消息并启动指数退避重连。
- 事务上下文传递：在事务中执行函数时，将连接状态绑定到当前进程字典（`put/2`），确保事务一致性。
- 超时控制：所有查询均支持可配置超时参数，防止长时间阻塞。

该架构支持多租户或多数据源场景，通过不同 `PoolName` 实现逻辑隔离。

**调用示例：**
```erlang
Settings = [{host, "localhost"}, {database, "mydb"}, {username, "user"}, {size, 10}],
ok = eadm_pgpool:connect(my_pool, Settings),
{ok, Rows} = eadm_pgpool:equery(my_pool, "SELECT * FROM users;", []).
```

**最佳实践建议：**
- 合理设置 `size` 与 `max_overflow`，避免资源耗尽。
- 长时间运行的事务应设置合理超时。
- 生产环境应监控连接池使用情况。

## 外部API接口服务

`api_payment.erl` 和 `api_watch.erl` 分别实现了支付网关对接与智能手表数据接收的外部API服务。

### 支付接口服务（api_payment.erl）

该模块集成支付宝与微信支付API，提供交易记录同步功能。通过 `fetch_alipay_transactions/2` 和 `fetch_wechat_transactions/2` 分别调用对应平台的账单查询接口。关键特性包括：
- 动态配置：API密钥、商户ID等通过 `application:get_env/3` 获取，便于多环境部署。
- 安全签名：支持RSA2签名算法，确保请求完整性。
- 自动化同步：`schedule_transaction_sync/0` 函数可定时拉取昨日交易数据。

**调用示例：**
```erlang
{ok, AlipayData} = api_payment:fetch_alipay_transactions("2025-05-15", "2025-05-16").
```

### 手表数据接口（api_watch.erl）

该模块接收来自智能手表的各类健康与定位数据，按 `type` 参数区分不同数据类型（如心率、血压、定位等）。每种类型对应不同的数据库表，通过 `eadm_pgpool:equery/3` 写入PostgreSQL。

支持的数据类型包括：
- 健康监测：心率（6）、血压（8）、血糖（10）、血氧（31）、体温（12/14）
- 运动数据：步数（4）、睡眠（58）、翻转（11）
- 定位信息：WIFI定位（5）、基站定位（3）、GPS定位（16）
- 告警事件：低电量（18）、跌倒（110）、表带破坏（39）等

所有告警事件均通过 `eadm_push:send_msg/1` 触发消息推送，实现即时通知。

**调用示例：**
```erlang
Params = #{<<"type">> => <<"6">>, <<"heartbeat">> => <<"75">>, <<"BTUtcTime">> => <<"2024-06-29 17:30:00">>},
Result = api_watch:index(#{params => Params}).
```

**最佳实践建议：**
- 外部API调用应添加熔断机制。
- 高频数据写入可考虑批量插入优化。
- 敏感数据传输需启用HTTPS。

## 通用工具函数模块

`eadm_utils.erl` 提供了一系列在项目中广泛复用的辅助函数，涵盖数据转换、时间处理、密码加密、日志记录等多个方面。

### 核心功能概述

| 功能类别 | 函数示例 | 说明 |
|--------|--------|------|
| JSON处理 | `to_json/1` | 将Erlang数据结构（元组、映射、PID等）转换为JSON兼容格式 |
| 时间处理 | `parse_date_time/1` | 解析 `"YYYY-MM-DD HH:MM:SS"` 格式字符串为Erlang时间元组 |
|           | `utc_to_cts/1` | UTC时间转+8时区（北京时间） |
|           | `time_diff/2` | 计算两个时间字符串的时间差（秒） |
| 日期生成 | `current_date_binary/0` | 获取当前日期二进制字符串 |
|           | `yesterday_date_binary/0` | 获取昨日日期 |
| 密码安全 | `pass_encrypt/1` | 使用SHA256加盐加密密码 |
|           | `verify_password/2` | 验证用户输入密码与数据库存储密码是否匹配 |
| 数据库结果处理 | `pg_as_map/2` | 将epgsql查询结果转换为键值映射 |
|                  | `pg_as_json/2` | 转换为含列名的JSON格式 |
| 日志与监控 | `log_info/1` | 记录定时任务日志，同时写入文件与数据库 |

### 特色功能

- **统一返回格式**：`return_as_map/1` 和 `return_as_json/1` 为HTTP接口提供标准化响应结构。
- **浮点数安全转换**：`binary_to_float/1` 和 `bin_to_float/1` 处理可能缺失小数点的二进制数字。
- **任务上下文日志**：`log_info/1` 自动获取当前任务ID（`current_job_id`），便于追踪定时任务执行情况。

**调用示例：**
```erlang
% 密码验证
case eadm_utils:validate_login(<<"admin">>, <<"mypassword">>) of
    1 -> login_success;
    2 -> user_not_found;
    3 -> user_disabled
end.

% 时间转换
BeijingTime = eadm_utils:utc_to_cts(<<"2024-06-29 09:30:00">>).
```

**最佳实践建议：**
- 所有数据库查询结果应使用 `pg_as_map/2` 统一处理。
- 用户密码必须使用 `pass_encrypt/1` 加密存储。
- 定时任务日志务必使用 `log_info/1` 以保证可追溯性。
