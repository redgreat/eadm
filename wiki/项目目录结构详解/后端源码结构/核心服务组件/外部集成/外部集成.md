## 微信集成

`eadm_wechat` 模块负责通过企业微信 Webhook API 发送消息。其核心函数 `send_msg/1` 接收一个二进制格式的消息内容，并将其封装为 JSON 请求体发送至企业微信。

该函数首先使用 `thoas:encode/1` 将 Erlang 映射（map）结构 `#{msgtype => 'text', text => #{content => Content, mentioned_list => ?WX_MENTIONS}}` 编码为 JSON 字符串。其中 `Content` 为待发送的文本内容，`?WX_MENTIONS` 是一个宏，定义为空列表，表示不提及特定成员。

随后，函数通过 `httpc:request/4` 执行 POST 请求。请求的目标 URL 由宏 `?WX_URL` 定义，其值为 `"https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=" ++ ?WX_KEY`。`?WX_KEY` 是从应用配置 `nova` 中获取的环境变量 `wx_key`，若未设置则使用默认的测试密钥。请求头 `?WX_HEADERS` 指定了 `Content-Type` 为 `application/json`。

整个发送过程被 `try...catch` 语句包裹，以捕获可能发生的异常（如网络错误）。若发送成功，函数返回 `#{<<"success">> => true}`；若失败，则记录错误日志并返回 `#{<<"success">> => false}`。

**本模块的错误处理机制简洁有效，通过 lager 框架记录详细的异常信息，并向调用者返回结构化的结果，便于上层逻辑进行判断和重试。**

## 支付系统集成

`api_payment` 模块集成了支付宝和微信支付两大平台的交易数据查询功能，并提供了定时同步的逻辑。

### 支付宝交易查询

`fetch_alipay_transactions/2` 函数用于获取指定时间范围内的支付宝交易记录。它首先检查 `?ALIPAY_APP_ID` 是否已配置，若未配置则直接返回错误。

在配置有效的情况下，函数构建一个包含 `app_id`、`method`、`charset`、`sign_type`、`timestamp`、`version` 和 `biz_content` 等字段的参数映射。`biz_content` 字段本身也是一个 JSON 字符串，包含了查询所需的 `start_time` 和 `end_time`。

签名是支付宝 API 的关键。函数调用内部函数 `build_sign_content/1` 生成待签名的字符串，然后使用 `sign_with_private_key/2` 和 `?ALIPAY_PRIVATE_KEY` 进行 RSA2 签名。签名结果被添加到参数映射中，最终通过 `httpc:request/4` 以 `application/x-www-form-urlencoded` 格式发送 POST 请求。

响应数据经 `thoas:decode/1` 解析后，函数检查 `code` 字段是否为 `"10000"`（表示成功），并返回相应的结果。

### 微信支付交易查询

`fetch_wechat_transactions/2` 函数用于获取微信支付的账单下载链接。与支付宝不同，微信支付 API 使用更复杂的认证机制。

函数首先构建请求 URL 和查询参数（`bill_date` 和 `bill_type`）。然后生成一个签名字符串，其格式为 `{METHOD}\n{URL_PATH}\n{TIMESTAMP}\n{NONCE}\n\n`。该字符串使用 `?WECHAT_PRIVATE_KEY` 进行签名。

认证头 `Authorization` 的值为 `WECHATPAY2-SHA256-RSA2048`，并包含商户号（`mchid`）、随机字符串（`nonce_str`）、签名（`signature`）、时间戳（`timestamp`）和证书序列号（`serial_no`）。

请求以 `GET` 方法发送，若成功，响应中会包含 `download_url`。函数随后调用 `download_bill_file/2` 下载实际的账单文件（该函数目前为占位符）。

### 定时同步逻辑

`scheduled_transaction_sync/0` 函数实现了定时同步的核心逻辑。它首先计算出“昨天”和“今天”的日期字符串作为查询范围。

然后，该函数依次调用 `fetch_alipay_transactions/2` 和 `fetch_wechat_transactions/2` 来获取两个平台的交易数据。对于成功获取的数据，它会调用 `process_alipay_transactions/1` 或 `process_wechat_transactions/1` 进行后续处理（目前这两个函数也是占位符）。若获取失败，则使用 `?LOG_ERROR` 记录错误日志。

此函数设计为可由定时任务（如 cron）定期调用，从而实现交易数据的自动化同步。

## 智能手表集成

`api_watch` 模块是智能手表数据的入口，其核心函数 `index/1` 根据传入参数中的 `type` 字段，将不同类型的数据分发到对应的数据库表中。

### 数据分发机制

`index/1` 函数接收一个包含 `params` 的映射。它通过 `maps:get(<<"type">>, Params, <<"0">>)` 获取 `type` 值，并使用 `case` 语句进行分发。

- **心率数据 (`type=6`)**：提取 `heartbeat` 和 `BTUtcTime`，将其插入 `lc_watchhb` 表。
- **血压数据 (`type=8`)**：提取 `diastolic`（舒张压）、`shrink`（收缩压）和 `BTUtcTime`，将其插入 `lc_watchbp` 表。
- **定位数据 (`type=5, 16`)**：提取经纬度（`Latitude`, `lngStr`）、速度（`speedStr`）和时间，将其插入 `lc_watchlocation` 表。
- **提醒数据 (`type=18, 19, ...`)**：当收到如“电量低”、“紧急预警”等提醒时，函数会将提醒信息插入 `lc_watchalarm` 表，并调用 `eadm_push:send_msg/1` 将消息推送给相关人员。

所有数据库操作均通过 `eadm_pgpool:equery/4` 执行，使用了 `ON CONFLICT ... DO UPDATE` 语句来处理重复数据，确保数据的最终一致性。

### 辅助函数

`bin_to_float/1` 是一个关键的辅助函数，用于将二进制字符串安全地转换为浮点数。它首先将二进制转换为列表，然后尝试使用 `list_to_float/1` 进行转换。如果原始字符串不包含小数点，`add_decimal_point/1` 函数会自动为其添加 `.0`，确保转换成功。该函数还包含了错误处理，当输入无效时会抛出异常。

## 配置示例与调用代码

### 配置示例

以下配置应放置在 `nova` 应用的环境变量中：

```erlang
% 微信 Webhook 配置
{wx_key, "your_actual_webhook_key_here"},

% 支付宝 API 配置
{alipay_api_url, "https://openapi.alipay.com/gateway.do"},
{alipay_app_id, "your_app_id"},
{alipay_private_key, "your_private_key"},
{alipay_public_key, "alipay_public_key"},

% 微信支付 API 配置
{wechat_api_url, "https://api.mch.weixin.qq.com"},
{wechat_app_id, "your_app_id"},
{wechat_mch_id, "your_mch_id"},
{wechat_api_key, "your_api_key"},
{wechat_api_v3_key, "your_api_v3_key"},
{wechat_serial_no, "your_certificate_serial_no"},
{wechat_private_key, "your_private_key"},

% 推送加 Token
{push_token, <<"your_pushplus_token">>}
```

### 调用代码示例

```erlang
% 发送微信消息
Content = unicode:characters_to_binary("这是一条测试消息！"),
Result = eadm_wechat:send_msg(Content).

% 同步昨日交易数据
ok = api_payment:schedule_transaction_sync().

% 处理手表心率数据 (模拟参数)
Params = #{<<"type">> => <<"6">>, <<"heartbeat">> => <<"75">>, <<"BTUtcTime">> => <<"2024-07-01 12:00:00">>},
WatchResult = api_watch:index(#{params => Params}).
```
