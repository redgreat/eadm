# EADM PostgreSQL 数据库设计规范

本规范适用于 EADM 自研 PostgreSQL 表、视图、序列、索引、函数、过程和触发器。它依据当前 `script/postgres/` DDL 与 Erlang/epgsql 代码编写，不适用于 Python、ORM 或其它项目。

## 1. 事实源与变更方式

- 当前 PostgreSQL 基线结构以 `script/postgres/datastruct.sql` 为事实源；初始化、FDW、pg_cron 和 Dashboard 过程分别位于同目录对应脚本。
- Erlang 代码不自动建表，不允许应用启动时执行全库 DDL。
- 新结构必须先设计迁移方案，再同步基线 DDL。仓库目前没有正式增量迁移目录，这是待补能力；建立前不得用修改基线脚本冒充生产迁移。
- 已部署数据库的变更必须提供独立、可审计、可回滚或有明确恢复步骤的迁移脚本。
- 禁止在生产库手工执行未入库 DDL；禁止改写已经执行过的迁移。

建议新增 `script/postgres/migrations/V0001__short_description.sql` 形式的只追加迁移。版本号一经使用不得复用。基线用于空库初始化，migration 用于存量库演进，两者最终结构必须一致。

## 2. 当前数据域

| 数据域 | 主要对象 | 用途 |
| --- | --- | --- |
| 系统 | `sys_dict`、`sys_cronlog`、`sys_proclog` | 字典、任务和过程日志 |
| 租户与认证 | `eadm_tenant`、`eadm_user`、`eadm_role`、`eadm_userrole` | 租户、用户、角色和授权关系 |
| 权限视图 | `vi_user`、`vi_role`、`vi_userrole`、`vi_userpermission` | API 查询与权限聚合 |
| 任务与看板 | `eadm_crontab`、`vi_crontab`、`eadm_dashboard` | 定时任务和看板汇总 |
| 设备 | `eadm_device`、`eadm_userdevice` | 设备及用户绑定 |
| 位置与健康 | `lc_carlocdaily`、`lc_watch*` | 轨迹、手表健康与告警数据 |
| 财务 | `fn_paybilldetail` | 支付账单明细 |

新增表先归入一个数据域；没有清晰归属时不要以 `tmp_`、`test_` 等名字直接进入正式基线。

## 3. 命名

- schema、表、列、索引、约束、序列、函数、触发器使用小写 `snake_case`。
- 延续现有域前缀：`eadm_` 业务主数据、`sys_` 系统数据、`lc_` 位置/健康、`fn_` 财务、`vi_` 视图。
- 主键约束：`pk_<表>_<列>`；唯一约束/索引：`uni_<表>_<语义>`；普通索引：`non_<表>_<语义>`；外键：`fk_<源列>_<目标表>_<目标列>`。
- 新序列使用 `seq_<表>_<列>`。`sd`、`et`、`eu`、`er`、`cr` 等短序列是存量兼容项，不复制到新表。
- 新触发器使用 `trg_<表>_lastupdate`。存量触发器名称保持兼容，除非有独立迁移。
- 不使用 PostgreSQL 保留字，不依赖双引号和大小写敏感标识符。

## 4. 主键与关联

- 业务实体优先使用无业务含义的稳定主键 `id`。现有 `CHAR(12)` 前缀 ID 继续兼容：`sd`、`et`、`eu`、`er`、`cr`。
- 新表若沿用字符 ID，使用 `CHAR(12)`、两位小写域前缀加 10 位序列，并登记前缀；若不需要跨系统可读 ID，优先 `BIGINT GENERATED BY DEFAULT AS IDENTITY`。
- 禁止新增 `serial`；存量 `serial` 不因无关需求改造。
- 关联表可使用 identity 主键，并对业务组合键增加唯一约束。
- 允许数据库外键。默认 `ON DELETE RESTRICT ON UPDATE RESTRICT`；级联操作必须有明确业务理由和删除影响说明。
- API 不得暴露或依赖序列当前值，业务代码不得通过 `max(id) + 1` 生成主键。

## 5. 标准审计与软删除字段

可修改的业务表沿用当前字段：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `createduser` | `varchar(50)` | 可空；记录创建人登录名或稳定 ID |
| `createdat` | `timestamptz` | `NOT NULL DEFAULT CURRENT_TIMESTAMP` |
| `updateduser` | `varchar(50)` | 可空 |
| `updatedat` | `timestamptz` | `NOT NULL DEFAULT CURRENT_TIMESTAMP`，由触发器更新 |
| `deleteduser` | `varchar(50)` | 软删除操作人 |
| `deletedat` | `timestamptz` | 软删除时间 |
| `deleted` | `boolean` | `NOT NULL DEFAULT FALSE` |

- 查询业务表默认增加 `deleted IS FALSE`。
- 软删除必须在同一事务设置 `deleted`、`deleteduser`、`deletedat`。
- 日志、流水、遥测等只追加表不强制使用完整审计字段，也不安装更新时间触发器。
- 历史表字段的可空性不一致是现状；新表按本节执行，旧表整改必须通过迁移。

## 6. 类型规则

- 时间点使用 `TIMESTAMPTZ`，数据库按 UTC 存储，API 输出明确时区或 ISO 8601；仅日历日期使用 `DATE`。
- 金额使用 `NUMERIC(18,2)` 或经业务论证的更高精度，禁止 `real`/`double precision`。
- 经纬度使用 `NUMERIC` 并记录精度；计算距离时明确坐标系。不得把坐标当普通字符串排序。
- 开关使用 `BOOLEAN`；多状态字段使用 `SMALLINT` 或短字符串，并用 `CHECK` 约束及列注释列出含义。
- 结构化权限和配置优先 `JSONB`。写入前在 service 层校验结构，按实际查询增加 GIN/表达式索引。
- 密码只保存项目既定的加密结果；Token、Cookie 密钥、支付密钥和数据库连接串不得进入业务表明文。
- 文本长度应来自业务上限；不确定且无需索引的长文本用 `TEXT`，不要随意使用超大 `varchar(n)`。

## 7. 约束、索引和视图

- 必须用数据库约束表达主键、非空、唯一性、合法状态与引用完整性，不能只依赖前端校验。
- 外键列、常用筛选列、排序列应依据真实查询建立索引；组合索引按等值过滤、范围过滤、排序的访问路径设计。
- 软删除表的唯一业务键使用部分唯一索引：

```sql
CREATE UNIQUE INDEX uni_example_code_active
    ON eadm_example (code)
    WHERE deleted IS FALSE;
```

- 不为每列机械建索引。新增/调整大表索引需要保存目标 SQL 的 `EXPLAIN (ANALYZE, BUFFERS)` 结果，并说明写入成本。
- 视图是 API 查询契约的一部分。变更 `vi_userpermission`、`vi_user`、`vi_role`、`vi_crontab` 等视图时必须同步 service、API 文档和权限测试。
- 避免在新视图中把时间预格式化为展示字符串；新接口优先返回类型化时间，由 API 层序列化。存量行为按兼容需求迁移。

## 8. SQL 与事务

- 所有外部输入都通过 epgsql 参数绑定传值，禁止字符串拼接值。
- 动态列名、排序方向、表名无法参数化时，只能由服务端白名单映射，不能透传请求参数。
- 多表写操作必须在同一事务完成；明确隔离级别、并发冲突处理和重试边界。
- 列表接口必须设置合理上限；大表禁止无条件全表返回。
- 禁止 N+1 查询，优先使用 JOIN、聚合或批量查询。
- 健康、财务、轨迹、认证数据属于敏感数据；查询必须在 SQL 前完成权限和数据范围检查，日志不得输出完整结果或敏感参数。

## 9. DDL 模板

```sql
CREATE SEQUENCE IF NOT EXISTS seq_eadm_example_id
    AS bigint START WITH 1 INCREMENT BY 1 CACHE 20;

CREATE TABLE IF NOT EXISTS eadm_example (
    id          char(12) NOT NULL DEFAULT
                ('ex' || lpad(nextval('seq_eadm_example_id')::text, 10, '0')),
    code        varchar(50) NOT NULL,
    name        varchar(100) NOT NULL,
    status      smallint NOT NULL DEFAULT 0,
    createduser varchar(50),
    createdat   timestamptz NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updateduser varchar(50),
    updatedat   timestamptz NOT NULL DEFAULT CURRENT_TIMESTAMP,
    deleteduser varchar(50),
    deletedat   timestamptz,
    deleted     boolean NOT NULL DEFAULT FALSE,
    CONSTRAINT pk_eadm_example_id PRIMARY KEY (id),
    CONSTRAINT ck_eadm_example_status CHECK (status IN (0, 1))
);

CREATE UNIQUE INDEX uni_eadm_example_code_active
    ON eadm_example (code) WHERE deleted IS FALSE;
CREATE INDEX non_eadm_example_status
    ON eadm_example (status, createdat DESC) WHERE deleted IS FALSE;

COMMENT ON TABLE eadm_example IS '示例域_示例信息';
COMMENT ON COLUMN eadm_example.id IS '示例主键(ex + 10位序列)';
COMMENT ON COLUMN eadm_example.code IS '业务编码';
COMMENT ON COLUMN eadm_example.status IS '状态(0启用,1禁用)';
COMMENT ON COLUMN eadm_example.deleted IS '软删除标记(false未删除,true已删除)';

DROP TRIGGER IF EXISTS trg_eadm_example_lastupdate ON eadm_example;
CREATE TRIGGER trg_eadm_example_lastupdate
BEFORE UPDATE ON eadm_example
FOR EACH ROW EXECUTE FUNCTION lastupdate();
```

模板中的 `lastupdate()` 是现有 PostgreSQL 基线函数。修改该函数会影响所有共用触发器的表，必须单独评审。

## 10. 多数据库同步

当前仓库保留 PostgreSQL、MySQL/TiDB、Kingbase、Oracle、DB2 脚本，但它们不是完全等价实现，运行时代码也固定使用 epgsql。因此：

1. 每次数据库变更先声明目标支持矩阵，不得笼统写“支持多数据库”。
2. PostgreSQL 是当前运行实现；其它脚本若不同步，必须在变更说明和兼容矩阵中记录。
3. 类型、序列、自增、JSON、布尔值、触发器、存储过程按目标数据库原生语法实现，不能仅做文本替换。
4. 每种声称支持的数据库都需要空库初始化和存量升级验证；未执行的数据库必须明确标为未验证。

## 11. 变更检查清单

- [ ] 数据域、表名、列名、ID 策略和所有状态含义已明确。
- [ ] 基线 DDL 与独立增量 migration 同步，且 migration 未修改历史版本。
- [ ] 主键、外键、唯一、非空、CHECK、默认值和软删除语义完整。
- [ ] 表和列均有注释，敏感字段与坐标系/时区/金额单位已说明。
- [ ] Erlang service 使用参数化 SQL，API DTO 与数据库字段解耦。
- [ ] 索引对应真实查询；大表变更评估锁表、磁盘、回滚和执行时长。
- [ ] 空库初始化通过，存量库迁移通过，重复执行策略和恢复步骤明确。
- [ ] 对应 PostgreSQL、其它目标数据库脚本、API、前端、导入导出和 wiki 已同步。
- [ ] 验证报告明确列出实际执行过的数据库版本，未验证项不声称通过。

## 12. 已知债务

- 尚无正式、只追加的 PostgreSQL migration 机制。
- 多数据库脚本覆盖不一致，MySQL/TiDB 当前缺少部分健康、位置与财务表。
- 存量表仍使用 `serial`、短序列名、展示型视图和不一致的审计字段约束。
- 部分脚本包含 destructive 的 `DROP ... CASCADE`，只适用于明确授权的空库重建，不能作为生产升级脚本。
- 需要建立数据库结构自动检查，以及关键 service 对真实 PostgreSQL 的集成测试。
